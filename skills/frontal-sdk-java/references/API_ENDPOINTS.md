# API Endpoints (Java SDK)

Source of truth: `contracts/sdk-endpoints.json` in the SDK repo (619 route entries, generated by `scripts/generate_endpoints.py`) and the `services/` resource classes. Every route is served under the API base URL, which defaults to `https://api.frontal.dev/v1`. The AI service is the exception: it uses `aiBaseUrl` (default `https://ai.frontal.dev`) and its routes have no `/v1` prefix.

Route paths below are relative to the base URL. `{param}` is a positional path parameter. Each route group has a method on the root client; resource clients are reached by chaining. Use `docs/api/*.md` in the SDK repo for per-service prose.

## Operation naming

Most generated resources expose the same verbs (see `CLIENT_PATTERNS.md`):

| Route shape | Java method |
| --- | --- |
| `GET /x` | `list(...)` |
| `POST /x` | `create(...)` |
| `GET /x/{param}` | `get(id, ...)` |
| `PUT /x/{param}` | `update(id, body, ...)` |
| `DELETE /x/{param}` | `delete(id, ...)` |
| `POST /x/{param}/<action>` | `<action>(id, body, ...)` |

Functions uses `PATCH` for update. Named helpers keep their action names (`health`, `rollback`, `stream`, `streamBlocking`, `waitForCompletion`).

## Workflows (verified helpers)

- `workflows().listPages(query, itemType)` returns `PageResult<T>`.
- `workflows().waitForCompletion(executionId, interval, timeout)` polls `workflows().executions().get(...)`.

## Functions

Functions routes are not in `contracts/sdk-endpoints.json` or the shared OpenAPI snapshot. The Java client carries its own route catalog in `FunctionsEndpoints`. Routes are defined in the SDK source; the Functions guide in the SDK repo (`docs/api/functions.md`) also lists them.

| Java call | HTTP |
| --- | --- |
| `functions().create(FunctionDefinition)` | `POST /functions` |
| `functions().list(QueryParams)` / `list()` | `GET /functions` |
| `functions().get(functionId)` | `GET /functions/{id}` |
| `functions().update(functionId, FunctionDefinition)` | `PATCH /functions/{id}` |
| `functions().delete(functionId)` | `DELETE /functions/{id}` |
| `functions().versions().list(functionId, query)` / `list(functionId)` | `GET /functions/{id}/versions` |
| `functions().versions().get(functionId, version)` | `GET /functions/{id}/versions/{version}` |
| `functions().versions().publish(functionId, version)` | `POST /functions/{id}/versions/{version}/publish` |
| `functions().deployments().deploy(functionId, version)` | `POST /functions/{id}/versions/{version}/deploy` |
| `functions().deployments().status(functionId, version)` | `GET /functions/{id}/versions/{version}/deployment/status` |
| `functions().executions().invoke(FunctionInvocationInput)` | `POST /functions/invoke` |
| `functions().executions().invokeAsync(FunctionInvocationInput)` | `POST /functions/invoke-async` |
| `functions().executions().getExecution(executionId)` | `GET /functions/executions/{id}` |
| `functions().executions().getResult(executionId)` | `GET /functions/executions/{id}/result` |
| `functions().executions().listExecutions(query)` / `listExecutions()` | `GET /functions/executions` |
| `functions().executions().cancelExecution(executionId)` | `POST /functions/executions/{id}/cancel` |

Models: `FunctionDefinition` (builder requires `name`, `runtime`, `entrypoint`), `FunctionRuntime` (`NODEJS20`, `NODEJS22`, `PYTHON311`), `FunctionInvocationInput(functionId, [version], [input])`, `FunctionInvocationResult`, `FunctionResource` (`id()`, `name()`, `status`, `version`, and so on), `FunctionStatus` (`DRAFT`, `ACTIVE`, `DEPRECATED`, `FAILED`). Schemas and inputs are caller-defined `JsonNode` values.

## Known gaps and conflicts

- `react()` is a client with no routes in `contracts/sdk-endpoints.json`.
- The catalog defines 11 `/integrations/...` routes (for example `GET /integrations/{param}` and `GET /integrations/{param}/action-runs`). No Java accessor exposes them.
- `docs/OVERVIEW.md` says the SDK exposes 611 named operations. The catalog has 619 entries. Treat the catalog as the count of record.
- The shared OpenAPI snapshot (`openapi.spec3.json`, paths carry a `/v1` prefix) matches 396 of the 619 catalog routes by method and path. Every route in `agents`, `billing`, `blob`, `governance`, `lineage`, `schedules`, `webhooks`, `connectors`, `audit`, and most of `ai` (8 of 9), `auth` (58 of 66), `observability` (22 of 31), and `workflows` (23 of 30) is absent from that snapshot. `data`, `ontology`, `events`, `providers`, `invocations`, and `webhook-endpoints` match fully. The Java route catalog is ahead of or divergent from the shared spec, so verify a route against the live API before relying on it.
- The Java SDK does not add an `Idempotency-Key` header. Writes run once and are not retried.
